# CentralHub 项目分析报告

## 1. 项目概述

CentralHub 是一个基于 Go 和 Gin 框架开发的域名管理平台，主要提供域名管理、DNS 解析、ICP 备案和 Volcengine CDN 集成等功能。项目采用 Docker 容器化部署，支持开发和生产环境，并提供了完善的开发工具链和文档。

### 1.1 核心功能

- **域名管理**：创建、查询和管理域名
- **DNS 解析**：域名解析服务
- **ICP 备案**：中国大陆域名备案查询和验证
- **CDN 集成**：与 Volcengine CDN 服务集成
- **域名所有权验证**：通过 DNS TXT 记录或文件上传验证域名所有权
- **审计日志**：记录系统操作

### 1.2 技术栈

- **后端框架**：Go + Gin
- **数据库**：MongoDB
- **日志**：zerolog 结构化日志
- **容器化**：Docker + Docker Compose
- **开发工具**：Air (热重载)
- **HTTP 客户端**：自定义封装的 HTTP 客户端

## 3. 核心组件分析

### 3.1 HubServer

HubServer 是应用的核心组件，负责处理 HTTP 请求并协调各个服务。它包含以下主要功能：

- **HandleCreate**：处理域名创建请求
- **HandleQuery**：处理域名查询请求
- **HandleOwnershipCheck/Verify**：处理域名所有权验证

HubServer 通过 Workflow 组件执行具体的业务逻辑。

### 3.2 Workflow

Workflow 组件负责编排域名管理的业务流程，主要包括：

- **CreateDomain**：域名创建流程
- **makeCname**：生成 CNAME 记录
- **createVendorDomain**：调用供应商 API 创建域名

Workflow 设计为可扩展的任务执行引擎，未来可以抽象为更通用的工作流引擎。

### 3.3 数据模型

项目定义了多个数据模型，核心包括：

- **CDNDomain**：CDN 域名配置，包含缓存、代理、访问控制等配置
- **XLDomain**：平台管理的域名，包含平台信息和 CDN 配置
- **CreateDomainRequest/Response**：API 请求/响应模型
- **ICPResponse/Data**：ICP 备案信息

### 3.4 存储层

Store 组件负责数据持久化，使用 MongoDB 作为数据库：

- **DomainStore**：域名数据的 CRUD 操作
- 支持按 ID 查询、更新和删除域名

### 3.5 客户端层

项目实现了多个客户端来与外部服务交互：

- **HTTPClient**：通用 HTTP 客户端，支持重试、超时等高级功能
- **DNSClient**：DNS 服务客户端
- **ICPClient**：ICP 备案查询客户端
- **VolcClient**：Volcengine CDN 服务客户端
- **MockClient**：测试用模拟客户端

### 3.6 配置管理

配置系统支持多环境配置：

- **ServerConfig**：服务器配置（端口、模式、超时）
- **DatabaseConfig**：数据库配置（MongoDB 连接）
- **LoggerConfig**：日志配置（级别、输出、文件设置）
- **ExternalConfig**：外部服务配置（Volcengine 凭证）

### 3.7 日志系统

使用 zerolog 实现结构化日志：

- **RunLogger**：业务逻辑日志
- **AuditLogger**：审计日志（HTTP 请求）
- 支持日志分割和多输出目标

### 3.8 中间件

- **AuditLog**：记录 HTTP 请求的审计日志
- **AuditLogWithReqID**：带请求 ID 的审计日志

## 4. 关键流程分析

### 4.1 域名创建流程

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ HTTP请求    │ --> │ 预检查      │ --> │ 创建域名    │
│ /create     │     │ 所有权/备案 │     │ 工作流      │
└─────────────┘     └─────────────┘     └─────────────┘
                                              │
                                              v
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ 返回响应    │ <-- │ 创建任务    │ <-- │ 生成CNAME   │
│ 任务ID      │     │ 记录        │     │ 记录        │
└─────────────┘     └─────────────┘     └─────────────┘
```

1. 接收域名创建请求
2. 进行预检查（域名所有权、备案状态）
3. 生成 CNAME 记录
4. 调用供应商 API 创建域名
5. 返回任务 ID 和状态

### 4.2 域名所有权验证流程

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ 发起验证    │ --> │ 生成验证    │ --> │ 返回验证    │
│ 请求        │     │ 值          │     │ 信息        │
└─────────────┘     └─────────────┘     └─────────────┘
       │                                       │
       │                                       v
       │                               ┌─────────────┐
       └──────────────────────────────>│ 用户添加    │
                                       │ DNS记录/文件│
                                       └─────────────┘
                                              │
                                              v
                                       ┌─────────────┐
                                       │ 验证请求    │
                                       │ /verify     │
                                       └─────────────┘
                                              │
                                              v
                                       ┌─────────────┐
                                       │ 检查验证    │
                                       │ 状态        │
                                       └─────────────┘
```

1. 用户发起域名所有权验证请求
2. 系统生成验证值（DNS TXT 记录或文件内容）
3. 用户在域名 DNS 中添加 TXT 记录或上传文件
4. 用户提交验证请求
5. 系统检查验证状态并返回结果
